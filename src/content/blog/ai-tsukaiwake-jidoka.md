前回の [AI の使い分け実践](/blog/ai-tsukaiwake-jissen/) では、「Claude で段取り → 別の AI で実装 → Claude で確認」という流れを、**人が間に立つ手動リレー**で回す話をしました。

今回はその先、<mark>手動リレーを少しずつ「自動化」していく</mark>話に踏み込みます。

とはいえ、いきなり全自動を目指さなくて大丈夫です。
自動化には段階があり、一歩ずつ進めれば十分。
つなぐ土台となる **MCP** も含めて、やさしく見ていきましょう。

## 自動化＝「人が間に立つ」を減らすこと

![自動化は3段階。手動リレー（人がコピペ）、半自動（手順をテンプレ化）、自動（AI が自分で道具を呼ぶ）。進むほど人の手間が減る。](/diagrams/ai-jidoka-3step.svg)

そもそも自動化とは、<mark>今まで人がやっていた「橋渡し」を、少しずつ機械に任せること</mark>です。

手動リレーでは、あなたが AI の間に立って、コピペで結果を運んでいました。
自動化とは、この「運ぶ・つなぐ」手間を減らしていくこと。
図のように、**手動リレー → 半自動 → 自動** と、3段階で人の手間が減っていくイメージです。

大事なのは、<mark>一足飛びに全自動を目指さないこと</mark>です。
今の段階でつまずいていないか確かめながら、一歩ずつ進めましょう。

## つなぐ土台は MCP

![MCPでつなぐ自動化。指揮役の AI が、共通の差込口MCPを通して、道具・別の AI・データを自分で呼び出す。](/diagrams/ai-jidoka-mcp.svg)

自動化のカギになるのが **MCP** です。
MCP は、<mark>AI に「外の道具」を持たせるための共通の差込口</mark>のこと。くわしくは [MCP サーバーとは何か](/blog/mcp-server-toha/) をどうぞ。

MCP でつないでおくと、指揮役の AI が、人のコピペを待たずに **自分で** 必要なものを取りにいけます。

- ファイルやカレンダーなどの **道具**
- 社内の資料などの **データ**
- そして、コーディングが得意な **別の AI**

最後の「別の AI を道具として呼ぶ」連携も、少しずつ出てきています。
つまり、<mark>指揮役の AI が MCP 越しに実装役の AI を呼ぶ</mark>。そんな自動化が、だんだん現実になりつつあります。

## 自動化の3ステップ

では、実際にどう進めるか。無理なく登れる3段のはしごです。

![中心のハブから光の筋が複数の道具や歯車へ自動で伸び、人の手を借りずに動いている。つなぎが自動化されたイメージ。](/img/ai-tsukaiwake-jidoka-1.webp)

**① 手動リレー（まずここから）**
人がコピペで、AI どうしをつなぎます。道具は不要で、今日から始められます。

**② 半自動（手順を覚えさせる）**
毎回同じ流れなら、その手順を "登録" しておきます。
プロジェクト共通の決まりは [CLAUDE.md](/blog/claude-md-toha/)、作業のやり方は [Skills](/blog/claude-skills-toha/) に覚えさせると、指揮役が段取りを一気に出してくれます。
コピペの回数がぐっと減る段階です。

**③ 自動（AI が自分で呼ぶ）**
MCP やエージェントのしくみを使い、指揮役の AI が自分で道具や別の AI を呼び出します。
ここまで来ると、あなたは目標を渡すだけ。あとは AI のチームが動きます（→ [AI エージェントとは何か](/blog/ai-agent-toha/)・[外へ広がる](/blog/ai-agent-renkei/)）。

<mark>いま自分が①〜③のどこにいるかを意識する</mark>と、次の一歩が見えやすくなります。

## どこまで自動化する？

「全部おまかせ」が一番えらい、わけではありません。
自動化するほど速くなりますが、<mark>暴走したときの影響も大きくなる</mark>からです。

コツは、影響の小さいところから自動化し、大事な操作には確認を残すことです。

- はじめは、実行前に「これで進めていい？」と確認が入る設定で使う
- 決まりきった安全な作業は、おまかせにする
- 消す・送る・お金が動くなど、取り返しがつきにくい操作は、確認を残す

このあたりの調整は [Claude Code の自動モード](/blog/claude-code-auto-mode/) と [Claude Code の安全設定](/blog/claude-code-anzen-settei/) が参考になります。

## 自動化するほど気をつけたいこと

人の手が離れるぶん、事前の備えが大切になります。
難しく考えず、次の3つを押さえておきましょう。

- **権限を絞る**：AI につなぐ道具やデータは、必要な範囲だけに限定する。
- **鍵を大切に**：外部サービスにつなぐ鍵（API キー）は、パスワードと同じ扱いで管理する。
- **外から来る情報を鵜呑みにさせない**：メールや Web ページに、AI をだます命令が仕込まれていることがあります（→ [プロンプトインジェクションとは](/blog/prompt-injection-toha/)）。

自動でつなぐ相手が増えるほど、入れてよい情報の線引きも大切になります。
[AI に入れてはいけない情報](/blog/ai-kojinjoho-chuiten/) や [AI を使うときの注意点](/blog/ai-anzen-chuiten/) もあわせてどうぞ。

## よくある疑問

**Q. いきなり全部を自動化しないとダメですか？**
いいえ。手動リレー → 半自動 → 自動、と3段階で少しずつで十分です。一足飛びに全自動を目指さなくて大丈夫。

**Q. 会社をまたいで AI どうしを自動でつなげますか？**
少しずつ可能になってきていますが、まだ専用の道具や設定が必要です。土台は MCP。まずは身近な自動化から始めましょう。

**Q. 自動化したら、確認はしなくていいですか？**
確認は残すのが基本です。とくに取り返しのつきにくい操作は、実行前に確認をはさむ設定にしておくと安心です。

## まとめ

手動リレーは、少しずつ自動化していけます。
大切なのは、一気に全自動を目指さず、段階を踏むことです。

- 自動化＝「人が間に立つ」手間を減らすこと
- つなぐ土台は MCP（AI に外の道具・データ・別の AI を持たせる差込口）
- 手動リレー → 半自動（テンプレ化）→ 自動（AI が自分で呼ぶ）の3段階
- 速くなるほど確認と備え（権限・鍵・外の情報）が大切

まずは、今の手動リレーで「毎回同じだな」と感じる手順を、一つだけテンプレ化してみてください。
そこから半自動へ、そして自動へ。無理のないペースで、AI のチームを育てていきましょう。
