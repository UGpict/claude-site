前回は [MCP サーバー](/blog/mcp-server-toha/) の話をしました。
今回は、それとよく一緒に語られる **Skills（スキル）** です。
ひとことで言えば、<mark>AI に「得意技」を覚えさせておくしくみ</mark>です。

AI にお願いするとき、毎回こまかく手順を説明していませんか。
「まずこうして、次にこうして、最後にこの形式でまとめて」。同じ説明の繰り返しは、地味に疲れます。
その「いつものやり方」をひとまとめにして、名前をつけて覚えさせておけるのが Skills です。

この記事では、Skills とは何か、なぜ便利なのか、CLAUDE.md や MCP とどう違うのか、そして作り方までを順にやさしく見ていきます。

## Skills とは — 手順書に名前をつけて渡しておく

![開いた道具箱から、得意技をあらわす光る玉が浮かび上がる。決まったやり方をAIに得意技として覚えさせるイメージ。](/img/claude-skills-toha-1.webp)

Skills は、<mark>特定の作業のやり方をひとまとめにした「手順書」</mark>です。
「この作業をするときは、こういう順番で、こういう作法でやってね」という内容を、一枚のファイルに書いておきます。

たとえるなら、料理のレシピカードです。
「カレーを作って」と言えば、AI がレシピカードを取り出して、その手順どおりに進めてくれる。
毎回材料と工程を口で説明しなくても、カード一枚渡しておけば済む、というイメージです。

このブログにも、実は記事を書くためのスキルがあります。
「記事を書いて」とお願いすると、AI が「記事作りのレシピカード」を開いて、トーンや構成、公開手順まで、決まった作法で書いてくれます。

それだけではありません。
実際に運用するなかで、記事に載せる図（[Mermaid](/blog/mermaid-ai/)）を描くスキルや、サムネイルの背景を画像 AI で作るスキルも、必要になったつど作り足してきました。
どれも「毎回同じ説明をしていたこと」を、一枚のカードにしたものです。

## どう呼び出される？ — 必要なときだけ開く

Skills のうれしいところは、<mark>必要なときにだけ呼び出される</mark>点です。

呼び出され方は、大きく2通りあります。

- **自動で**：お願いの内容に合うスキルがあれば、AI が自分で「これを使おう」と判断して開きます。
- **名前を指定して**：`/スキル名` のように、自分から名指しで呼び出すこともできます。

ふだんは眠っていて、関係する作業のときだけ目を覚ます。
だから、スキルをたくさん用意しても、いつもの会話が重くなりません。
「使うときだけ取り出すレシピカード」なので、増えても邪魔にならないわけです。

## CLAUDE.md・MCP との違い — 役割が三つに分かれている

ここが混乱しやすいところなので、整理しておきます。
Claude Code には、似ているようで役割の違う三つの道具があります。

![役割が三つに分かれる。CLAUDE.mdはいつもの常識、Skillsは特定作業の得意技、MCPは外の道具。競合せず組み合わせて使う。](/diagrams/skills-3-roles.svg)

![CLAUDE.md・Skills・MCPの役割の違い。CLAUDE.mdは毎回読む常識、Skillsは必要なときだけ開く得意技、MCPは外の道具をつなぐ差込口。](/tech/skills-vs.svg)

| しくみ | たとえ | いつ効く |
| --- | --- | --- |
| CLAUDE.md | うちの常識・ハウスルール | 毎回いつも |
| Skills | 得意技・レシピカード | 必要な作業のときだけ |
| MCP | 外の道具の差込口 | 外部とやりとりするとき |

- **[CLAUDE.md](/blog/claude-md-toha/)** は、毎回かならず読まれる「常識」。短く、いつも効かせたいルール向き。
- **Skills** は、特定の作業のときだけ開く「手順書」。長めの段取りやお決まりの型向き。
- **[MCP](/blog/mcp-server-toha/)** は、ファイルや外部サービスをつなぐ「差込口」。道具そのものを増やす役割。

かんたんに言えば、<mark>いつもの心得は CLAUDE.md、特定作業の段取りは Skills、外の道具は MCP</mark>。
この三つは競合しません。組み合わせて使うものです。

（似たものに、あなたのことを自動で覚えてくれる「メモリー」もあります。Skills との違いは [メモリーとは何か](/blog/claude-memory-toha/) で整理しています。）

## 何がうれしいのか — 「毎回の説明」から解放される

Skills のありがたみは、同じ作業を繰り返す人ほど大きくなります。

- 毎回のこまかい指示を、一度書けば使い回せる
- 手順が決まっているので、仕上がりがブレにくい
- チームで共有すれば、みんな同じ作法で作業できる

たとえば「議事録は必ずこの見出しで、最後に決定事項を箇条書きにする」といった型。
一度スキルにしておけば、次からは「議事録まとめて」の一言で、いつも同じ形に整います。
<mark>説明する手間と、出来上がりのバラつきが、まとめて減る</mark>のが最大の効果です。

## 作り方 — 手順を Markdown で書くだけ

作り方はとてもシンプルです。
決まった場所にフォルダを作り、その中に `SKILL.md` という一枚を置きます。
先頭に「名前」と「どんなときに使うか」を書き、続けて手順を書くだけです。

```markdown
---
name: meeting-notes
description: 会議の文字起こしから議事録を作るときに使う。決まった見出しでまとめる。
---

# 議事録の作り方

1. 参加者と日時を冒頭にまとめる
2. 話題ごとに `##` の見出しで整理する
3. 最後に「決定事項」を箇条書きにする
4. 口調は「です・ます」でそろえる
```

コツは、**`description`（どんなときに使うか）をていねいに書く**ことです。
AI はここを読んで「今の作業にこのスキルが合うか」を判断します。
ここが曖昧だと、せっかく作っても呼び出してもらえません。

あとは、手順を人に教えるつもりで書けば大丈夫です。
プログラミングの知識はいりません。<mark>文章で段取りを書くだけで、立派なスキルになります。</mark>

そのままコピペして使えるテンプレートと記入例は、[自分だけの「スキル」を作ってみる](/blog/claude-skill-tsukuru/) にまとめました。

## 使いどころの見きわめ

なんでもスキルにすればいい、というものでもありません。
迷ったときの目安です。

- **いつも効かせたい短いルール** → CLAUDE.md へ
- **特定の作業の、決まった段取り** → Skills へ
- **一回きりのお願い** → その場で説明すれば十分

「同じ手順を三回説明したな」と感じたら、スキルにするサインです。
逆に、たまにしかやらないことまで作り込むと、管理が増えるだけになります。

## よくある疑問

**Q. Skills と CLAUDE.md はどう違いますか？**
CLAUDE.md は毎回必ず読まれる「常識」、Skills は必要なときだけ開く「得意技」です。短い心得は CLAUDE.md、特定作業の手順は Skills が向いています。

**Q. プログラミングの知識は必要ですか？**
基本は不要です。手順を Markdown（文章）で書くだけで作れます。

**Q. 自分で作らないと使えませんか？**
いいえ。用意されたスキルを選んで使うこともできますし、自分の手順を一枚書き足すだけでも役立ちます。

## まとめ

Skills は、AI に「得意技」を覚えさせておくしくみです。
毎回の細かい説明を一度書いておけば、必要なときにだけ取り出して、いつも同じ作法で作業してくれます。

- Skills＝特定の作業の手順書に名前をつけたもの
- 必要なときだけ呼び出されるので、増えても重くならない
- CLAUDE.md（常識）・MCP（差込口）とは役割が違う。組み合わせて使う
- 作り方は `SKILL.md` に手順を書くだけ。`description` をていねいに

まずは、あなたが「毎回同じ説明をしているな」と感じる作業をひとつ、手順として書き出してみてください。
書き出したその手順が、あなただけの最初のスキルになります。
