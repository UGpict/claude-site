# spec: CHAOS BEAT（カオス振り子ストップの作り替え）

二重振り子を狙って止めるスコアゲームを、**リズム×カオスで「60秒で1曲を遊び切る」ゲーム**に作り替えたもの。
60秒は単純延長ではなく、INTRO → GROOVE → BUILD → CLIMAX → FINAL の**セクション制**で、譜面と音楽に起承転結がある。
物理エンジン（RK4 二重振り子）はそのまま流用し、ゲームループと採点・演出・音を変えている。

- 対象ページ：`/games/chaos-pendulum/`（作り替え。別ページは作らない）
- 物理：`src/scripts/games/chaos-pendulum.ts` の RK4 二重振り子計算は維持（挙動を変えない）
- 音・通信・計測・保存：エンジンからは分離（onEvent 経由）

> この文書は**現行仕様**だけを書く。廃止した案は末尾「廃止済み仕様」にまとめてあり、現行仕様として扱わないこと。

## 不変条件（変えるときは spec から直す）

1. **1曲 = 60秒（セクション制）**：ゲーム本編は曲データ（`SongDefinition.duration`）の 60 秒。時間延長ボーナスは導入しない。
   カウントインは本編に含めない。尺は `song.ts` の曲定義だけで決まり、`GAME_TIME` のような定数を散在させない
   （将来 QUICK 30 / FULL 90 は曲定義を足すだけで作れる。ただし今回モード選択 UI は作らない）。
2. **リズム整合（timeScale = 1）**：ターゲットが存在している通常プレイ中は物理の `timeScale = 1` を維持する。
   理由：音の入力拍と未来軌道予測を一致させるため。物理時間の速度を変える仕組み（FEVER 速度・アシスト・難易度別速度）は入れない。
   スローは「叩いた直後（hit → 次の的が出るまでの約0.2秒）」だけ。
3. **共通 beat grid**：BGM の拍頭・cue（タン/ドン）・`target.hitAt`・アプローチリングの収束は、すべて
   `beatTime = transportStart + beatIndex × SPB` の同じ beatIndex で決まる。「BPM が同じ」ではなく「同じ拍の上にある」こと。
4. **判定は距離ベース**：押した瞬間の先端 ↔ 的中心の距離で判定する（タイミングのズレは計測するが判定には使わない）。
5. **物理は不変**：`deriv/rk4/tips` と固定タイムステップ（1/300 秒）は変えない。

## コアループ
- **TAP TO START**：ページを開くと振り子の静止プレビュー＋「CHAOS BEAT / 音を聞いてタイミングを狙え / [TAP TO START] /
  タップ / クリック / Space」のオーバーレイ。ユーザー操作で AudioContext を起こしてから始める（初回の無音・位相ズレを防ぐ）。
- **カウントイン**：開始操作のあと 4 拍（タン・タン・タン・タン → 拍0で GO のドン、画面に 3・2・1）。拍0 が gameTime=0。
- 黄色いターゲット（円）が**1つずつ**出る。「叩く」入力（タップ／クリック／スペース）の瞬間の、
  **先端おもり ↔ ターゲット中心の距離**で判定する。
- **ターゲットはリズムパターンの入力拍に対応する未来軌道点に置く**（リズム×カオスの核）。
  パターン先頭を「次の拍頭」に合わせ、`hitAt = beatTime(次の拍 + hitBeat)`。その時刻の予測軌道位置に的を出す。
  = 音（タン・タン・ドン）でタイミングが分かり、振り子を目で見て微調整すると PERFECT。
- **寿命**：`hitAt + 1.2拍` を過ぎたら見逃し MISS（コンボ切断）→ すぐ次の的。「じっと待つ」を最適戦略にしない。
- **BPM 脈動**：ターゲットは 130 BPM の拍頭で「ドクン」と膨らむ。音が出ない環境でも視覚の脈動は出す。
- 叩いた瞬間 **約0.2秒スロー → 判定表示 → 次のターゲット**。振り子はリセットしない。
- **slowmo 中は入力無効**（`state !== 'playing'` なら無視）。連打で判定が暴れるのを防ぐ。
- 60秒（最終拍）で曲が終止 → **FINISH!**＋終止音 → 約1.3秒後に結果パネル（スコア＋最大コンボ）→ **即リトライ**（[もう一回]／Space／Enter）。
  リトライも初回と同じ開始経路（transport 張り直し → カウントイン → 開始）を通る。

## 曲のセクション（1曲60秒）
セクションは**曲そのものの進行**（譜面の性格＋基本アレンジ）。境界は設計値の秒を**最寄りの小節頭**に丸める
（BGM の切替・`section_change`・譜面プール切替が全部同じ拍で起きる）。

| セクション | 設計値 | 実境界（130BPM・小節頭） | 譜面プール | 的サイズ | 基本アレンジ |
| --- | --- | --- | --- | --- | --- |
| INTRO | 0–10 秒 | 0 – 9.23 | easy（A/B のみ・裏拍なし） | ×1.15 | キック中心・音数少なめ |
| GROOVE | 10–25 | 9.23 – 25.85 | easy＋standard（C/D/E が1つ入る） | ×1.0 | 通常ドラム（クラッシュで開始） |
| BUILD | 25–40 | 25.85 – 40.62 | standard＋build（繰り返し→崩し・裏拍増） | ×1.0 | 8分シェイカーで密度UP、メロディ変奏、最後の1小節にスネアロール |
| CLIMAX | 40–55 | 40.62 – 55.38 | build＋climax（裏拍入力 C/G・詰め E/F） | ×0.92 | 伴奏パッド（Dm–B♭–C–A）、メロディ強め、ベースが和音に追従 |
| FINAL | 55–60 | 55.38 – 60.00 | final（短い締め2つ） | ×0.92 | 4つ打ち、締めモチーフ、最終拍で終止音 |

- **section と combo は別概念の二層構造**：section → 基本アレンジ（コンボ無関係に鳴る）／combo → 層の解放（bass/hihat/melody/FEVER lead）。
  CLIMAX でも combo 0 なら melody は鳴らない。セクションが変えるのは melody 層が弾く**モチーフと音量**だけ。
- **物理速度は全セクション同じ**（timeScale=1 不変）。難しさは譜面・的サイズ・リズムパターンで作る。
- **FINAL**：セクション名「FINAL 5」を表示、キャンバス背景に 5→4→3→2→1 を薄く大きく（2拍ごと＝最終拍で終止）、
  枠が拍で明滅、残り秒数と時間バーをピンクで強調。最後の入力拍は終止拍の1拍以上前に置く（収まらなければ的を出さずに終止を待つ）。
- **表示**：セクションが変わった小節頭に、キャンバス下端へセクション名を約1秒フェード表示。HUD に残り秒数（TIME 60→0）。

## 判定（距離ベース）
内部の 0〜100 点の距離採点は分析用に残すが、**得点になるのは GOOD 以上だけ**。

| 判定 | 条件（的中心からの距離 d、的半径 R） | 得点 | 表示 |
| --- | --- | --- | --- |
| PERFECT | d ≤ 0.35R | 90〜100 × 倍率 | 画面フラッシュ＋強SE |
| GREAT | d ≤ 0.7R | 70〜90 × 倍率 | 光る＋SE |
| GOOD | d ≤ R | 40〜70 × 倍率 | 軽いSE |
| NEAR MISS | R < d ≤ 1.25R | **0点** | 「◯秒早い/遅い！」（`gameTime − hitAt`） |
| MISS | d > 1.25R、または寿命切れ | **0点** | 「MISS」／寿命切れは「見逃し…」 |

- `NEAR MISS / MISS は 0 点`（部分点は連打ゲー化するため）。

## コンボ
- GOOD 以上で +1、NEAR MISS / MISS（寿命切れ含む）で 0。
- 倍率：`3 → ×1.2` / `5 → ×1.5` / `10 → ×2.0`。適用順は `判定 → コンボ+1 → 倍率再計算 → 今回分に加算`。
- 最大コンボをゲーム通して記録（ランキング指標）。

## CHAOS FEVER（強烈に気持ちいい報酬状態）
ルールは据え置き：PERFECT **3連続**で発火、5秒間、**得点 ×2**、MISS / NEAR（寿命切れ含む）で解除。倍率は ×2 のまま。
目的は「×2だから嬉しい」ではなく「FEVER に入ること自体が気持ちいい／切りたくない」。通常状態との差を極端にするが、
**cue・的の位置・アプローチリング・タイミングの読みやすさは絶対に損なわない**（演出はすべて描画と音だけ）。

- **突入（約0.7秒）**：白→黄の全画面フラッシュ（最初の約0.2秒だけ）、軽いズーム、巨大な「CHAOS / FEVER / ×2 SCORE」
  （的より奥に描く）、虹色の粒子を大量に。突入SE＝低音インパクト＋上昇ライザー＋高音スパークル。次の拍頭にクラッシュ。
  対応端末は短いバイブ。突入の打鍵では判定ラベル・コンボ節目表示を出さず、突入演出を主役にする。
- **FEVER 中の見た目**：的とアプローチリングが**拍に同期して虹色**に循環（yellow→pink→cyan→purple。位置・半径・判定は同じ）、
  軌跡が約1.8倍長く太く濃い pink→yellow→cyan グラデーション、背景が拍頭で pink/yellow に光る、虹の縁、
  上部に虹色の「CHAOS FEVER」＋「×2 SCORE · FEVER ×N」＋残り時間ゲージ。
- **FEVER ×N**：FEVER 中に GOOD 以上を取るたび +1 する**表示だけ**の連続数（倍率ではない）。
- **FEVER 中の PERFECT**：粒子増量、的から二段階の爆発、虹色の大きな PERFECT、巨大な「+xxx / FEVER ×2」（xxx は ×2 適用後の加算値）、
  描画だけの軽いカメラシェイク（約6px・0.1秒）。GOOD/GREAT/MISS では揺らさない。
- **音楽の解放**：FEVER 層＝lead＋5度上の合いの手＋オープンハット＋伴奏パッド（セクションに無くても）＋オクターブ上のメロディ。
  すべて BGM バス経由で、cue（ドン）前後のダッキングはそのまま効く。
- **解除の落差**：虹・太い軌跡・背景の明滅・FEVER 層が一瞬で消え、画面が一瞬暗く沈んで「FEVER END」、控えめな「シュン…」。
  MISS なら combo 0 で次の拍からセクションの基本アレンジだけになる。
- **FEVER のまま曲が終わる**：解除（MISS）扱いにせず、虹色の「FINISH!!」＋「CHAOS FEVER FINISH」＋粒子、
  終止音もオクターブ上の和音・駆け上がり・長いクラッシュ・深いサブで最も派手に。
- **FINAL との重なり**：FINAL の枠とカウントは FEVER 中は虹色。背景オーバーレイは合計上限つきで的が埋もれない。
- **prefers-reduced-motion**：シェイク・ズームなし、粒子 40%、フラッシュ 40%。音・スコアは同じ。
- **物理の速度は変えない**（不変条件2）。

## 難易度
差は **的の大きさ（targetR）・初期条件（初期角レンジ）・的を置く距離** で作る。物理の速度は全段同じ。
譜面パターンの複雑さはセクションの sequence pool で決まる（INTRO は A/B のみ → 後半ほど裏拍・詰め。全難易度共通）。

| 難易度 | targetR | 初期角 θ1 / θ2 |
| --- | --- | --- |
| 易しい | 0.55 | 1.9–3.0 / 1.6–3.1 |
| 普通 | 0.34 | 1.9–3.0 / 1.5–3.1 |
| 難しい | 0.20 | 1.9–3.0 / 1.4–3.1 |
| 鬼 | 0.13 | 2.2–3.3 / 2.0–3.3 |

## 音（Web Audio API のみ・外部音源なし）
- **BPM 130**（`beat-grid.ts` の1か所で定義）。
- **リズム予告（cue）**：各ターゲットに「タン・タン・ドン」。`RHYTHM_PATTERNS`（A〜G）をデータ駆動で持ち、
  セクションの sequence pool から選んだ譜面シーケンスを順番に消化。直前と同じシーケンスは避ける。
  追加パターン：E＝タン タタ タン ドン／F＝タン 休 タタ ドン／G＝タン タン ・タ ・ドン（裏拍入力）。どれも刻みを聞けばドンが予測できる。
- **持続BGM（実装済み）**：ゲーム中ずっと拍に同期して鳴るループ。コンボで層が増える。

  | 状態 | 鳴る層 |
  | --- | --- |
  | combo 0–2 | drum |
  | combo 3–4 | + bass |
  | combo 5–9 | + hihat |
  | combo 10+ | + melody |
  | FEVER | + lead |

  MISS / NEAR で combo=0 になったら、**次の拍からセクションの基本アレンジのみ**。層の切替は拍頭に同期。
- **曲の終止**：最終拍（60.00 秒＝拍130）で BGM ループを止め、D メジャーの和音＋キック＋クラッシュの終止音。
- **役割分担**：`judgment()` = 判定フィードバック SE のみ ／ BGM スケジューラ = 曲の層。
- **cue 最優先**：BGM は cue より明確に小さい（BGM マスター 0.5、ドンの音量はキックより大きい）。
  さらに accent（ドン）の −80ms〜+120ms だけ BGM を約 −5dB ダッキングする。

## 計測（GA4・既存 analytics 経由）
- `hit`：`kind / pts / score / combo / comboMult / maxCombo / distancePx / nearMissPx / timingOffsetMs / expired`。
- `game_over`：`score / maxCombo / hits / perfectCount / greatCount / goodCount / nearCount / missCount / expiredCount /
  averageAbsTimingOffsetMs / averageTimingOffsetMs / difficulty`。
- `game_start` / `game_retry`（difficulty 付き）：`game_retry ÷ game_over` で終了後の再プレイ率を見る。
- `section_change`：`section / elapsed / musicIntensity`（どのセクションで MISS が増えるかを hit と合わせて見る）。
- `game_over` に `sectionReached` は付けない（全員60秒完走するため）。
- FEVER：`fever_start` と `fever_end { reason: miss|timeout|finish, duration, hits }`。`game_over` に
  `feverCount / feverDuration / feverHits / feverPerfects`。イベントの種類・回数は増やしていない。
- **判定は変えない**。「音にぴったり合わせても PERFECT にならない」がデータで多いと分かった場合のみ、
  将来 timingOffset を補助条件にする（現時点では実装しない）。

## ランキング
- 今日／今週／歴代 × 難易度別タブ。指標は **スコア**（副キー：最大コンボ）。
- 60秒版はスコアレンジが約2倍。API の上限 `MAX_SCORE` は 40000（理論上限の見積もり≒17,000〜34,000）。
- 自己ベストは曲の尺ごとに別キー（`cb:best:60:<難易度>`）。30秒版の自己ベストは読まない。
- D1 の既存行（30秒版）は60秒版と比較不能。**切替時の初期化はオーナーが手動で行う**（自動 DELETE はしない。手順は plan 参照）。

## やらないこと（非目標）
- 動画キャプチャ、外部API・課金・サーバー音源、サーバー権威の本格アンチチート、別ゲームページの新設。
- 今回スコープ外（将来候補）：動く的、ボーナス的、新しい難易度、新しいランキング方式、曲の本格作曲（4〜8小節）、FEVER の倍率増（×3以上）や時間延長アイテム。

## 廃止済み仕様（Deprecated — 現行仕様ではない）
以下は過去の案・実装で、**すべて廃止**。コードにも docs の現行節にも戻さないこと。
- **30秒固定のスコアアタック（`GAME_TIME = 30`・全編同じテンション）**：60秒1曲のセクション制に置き換え。
  「TIME UP！」表示も「FINISH!」＋終止音に置き換え。序盤判定の `hits < 6` は INTRO の sequence pool に置き換え。
- **Magnet Assist**（的付近でスローにする易しさ補助）：timeScale ≠ 1 になり音とズレるため廃止。
- **難易度ごとの timeScale 変更／鬼の速度UP**：同上。難易度差は targetR・初期条件・譜面で作る。
- **FEVER 中の速度 ×1.3**：同上。FEVER は得点×2＋音と演出のみ。
- **青ターゲットの +2秒（時間延長）**：曲の尺（60秒）を固定で守るため不採用。
- **「曲レイヤー未実装」**という記述：持続BGMは実装済み。
- **判定SEに bass/hihat/melody の一発音を足す旧方式**：持続BGMの層に置き換え済み。
- **的の固定寿命 3秒／ランダムな未来点への配置**：入力拍（hitAt）基準の配置と `hitAt + 1.2拍` 寿命に置き換え済み。
- **BGM を `currentTime + 0.1` から別クロックで開始する方式**：共通 transport に置き換え済み。
